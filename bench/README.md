# 性能测量

`results.json` 保存一次 Node.js 本机测量，包含所有轮次的原始耗时、环境、版本和解析器文件摘要。首页通过 `site/performance-worker.js` 在访问者的浏览器中重新测量，不读取这个文件。

在包含 `v0.1.0` 标签的仓库检出中，使用支持原生 TypeScript 类型擦除的 Node.js（当前验证为 24.21.0）：

```sh
npm ci --prefix bench
npm run compare --prefix bench
```

基准依赖单独保存在这里，不进入库的运行时依赖或 npm 发布包。脚本从 Git 标签读取优化前的解析器到临时目录；不会修改解析器源码。运行会更新 Node.js 测量记录 `results.json`。

## 测量方法

三个输入均由脚本生成：2500 条嵌套记录、包含 262144 个普通字符的长字符串，以及 50000 个数字的数组。都使用 ASCII JSON，分别为 485421、262155、328901 字节。

各实现接收相同的异步字符串块，每块最多 4096 个 UTF-16 码元。先将完整结果与 `JSON.parse` 比较，再预热 3 次，轮换运行顺序测量 11 次，取完整解析耗时的中位数。`@streamparser/json` 开启 `emitPartialTokens` 和 `emitPartialValues`，`paths` 为 `['$']`；jsonriver 消费全部输出并取最后的根值。

这里测量有效输入的完整解析速度，不包含网络等待、UTF-8 解码、Vue 更新或内存占用。不同库的中间更新粒度与语法语义并不完全相同。三个输入也没有覆盖所有 JSON 形态，不能据此推断所有场景的性能；数字数组用于保留不受字符串优化直接改善的对照。

## 调优内容

v0.1.1 在主循环中为字符串值与键的普通字符增加 shortcut。正则 `/[^"\\\x00-\x1f]+/y` 从 `lastIndex` 指定的位置读取连续普通字符；一次追加匹配段，并根据匹配后的 `lastIndex` 跳过已消费位置。引号、反斜杠、控制字符及其他语法仍进入原来的状态函数。普通字符范围包含中文和其他非 ASCII 字符。

状态函数保持原样；字符串值的普通字符段在每个输入块中写回宿主，不必等到整个字符串闭合。对象键仍完整闭合后使用。合法输入的速度测量与非法输入的语法测试分别进行。
