# JSON 字符流解析器设计规范

本规范从 JSON 的文本语法独立推导一个 TypeScript 解析器。设计只有一个当前状态函数和一个实际容器栈；每个状态接收当前输入字符，执行本表规定的操作，返回下一个状态函数。状态总数为 **30**。解析器本身是生成器，逐字符输出解析指令，并返回最终 JSON 值。

本次交付止于设计文档。本文规定后续实现必须满足的行为，不宣称现有源码已经实现或验证了这些行为。

## 1. 接受的完整语法

```text
document = ws value ws
value    = object / array / string / number / "true" / "false" / "null"
object   = "{" ws [member *(ws "," ws member)] ws "}"
member   = string ws ":" ws value
array    = "[" ws [value *(ws "," ws value)] ws "]"
string   = quotation *string-character quotation
number   = ["-"] integer [fraction] [exponent]
integer  = "0" / nonzero-digit *digit
fraction = "." 1*digit
exponent = ("e" / "E") ["+" / "-"] 1*digit
ws       = *(space / tab / carriage-return / line-feed)
```

方括号在该语法中表示可选项，星号表示重复；引号内的符号表示输入字符。`quotation` 是 `"`，`digit` 是 ASCII `0`–`9`，`nonzero-digit` 是 ASCII `1`–`9`。

`string-character` 有两种形式：

- 原样字符：除 `"`、反斜杠和 U+0000–U+001F 以外的字符。
- 转义：反斜杠后接 `"`、反斜杠、`/`、`b`、`f`、`n`、`r`、`t`，或者 `u` 后接恰好四个十六进制数字。

根值可以是六种 JSON 类型中的任意一种：对象、数组、字符串、数字、布尔值和 `null`。其中布尔值有 `true` 和 `false` 两个语法分支，所以 `value` 共列出七个分支。每个文档只允许一个根值，根值之后只允许 JSON 空白。禁止注释、尾逗号、单引号字符串、未加引号的对象键、前导加号、非零数字前的额外零，以及不完整的小数或指数。

## 2. 字符来源与公开行为

字符是一项输入数据，字符来源是产出这些数据的迭代来源，两者不能混同。本设计用 Unicode 字符数值作为状态函数接收的字符表示；为兼容已有常用调用，也接受来源用单字符字符串表示字符。以下类型是本设计的选择，保留公开函数名及指令形状，不把旧参数声明当作用户已经批准的约束：

```ts
type Character = number;
type CharacterInput = Character | string;
type CharacterSource = Iterable<CharacterInput>;
type State = (char: Character) => State;
declare function parse(chars: CharacterSource): Generator<JsonInstruction, JsonValue, undefined>;
declare function parseValue(chars: CharacterSource): JsonValue;
declare function characters(chunks: Iterable<string>): Generator<string, void, undefined>;
```

`Character` 的有效值为 0–0x10FFFF 之间的整数。为保留 JavaScript JSON 字符串的 UTF-16 内容，U+D800–U+DFFF 也允许作为独立代理代码单元；这里没有把它们排除成“必须配对的 Unicode 标量值”。状态函数比较的是字符值，例如 `[` 对应 0x5B；追加原样字符或数字拼写时，追加该字符的 UTF-16 表示 `String.fromCodePoint(char)`，而不是数字的十进制文本。

`parse` 的输入是同步可迭代的字符来源，不要求来源为字符串，也不推测网络包、文件块或其他上游分段方式。它在生成器内部通过 `for...of` 取得每个字符项，验证并归一化为 `Character`，然后调用唯一的当前状态函数。归一化只检查并转换单个字符项，不扫描令牌、不决定 JSON 语法、不保留另一套状态。`parseValue` 完整消耗该生成器并返回结果。`characters` 只是可选的字符串块适配器，解析器不依赖它。

来源可以是直接产出上述字符数值的生成器、数值可迭代集合，或者产出单字符字符串表示的其他生成器。数值表示直接进入状态；字符串表示必须是恰好一个 UTF-16 代码单元，或长度为二的合法高低代理对，并归一化为相应字符数值。解析过程不询问这些字符最初来自字符串、文件、字节解码器还是计算过程。

例如一个来源依次产出 0x5B、0x31、0x5D，就直接表达文档 `[1]` 的三个字符；解析器不需要先把它们拼成输入字符串。字符值 0x31 表示字符 `1`，不是直接写入 JSON 数值 `49` 或 `1` 的指令；它仍须经过数字状态及完成条件。

裸 `Iterator<CharacterInput>` 仅承诺 `next()`，不保证能用于 `for...of`，因此不能直接作为本接口来源。来源必须提供 `[Symbol.iterator]()` 并返回一个字符迭代器；生成器通常已经同时实现 Iterator 与 Iterable，即 `IterableIterator`。已有裸 Iterator 可以由一个 `[Symbol.iterator]()` 返回该 Iterator 的包装对象适配，无需收集成数组或字符串，也无需增加解析器内部栈。

空字符串、两个普通字符、包含多个码点的块、非整数、越界数值、`NaN`、`Infinity` 以及其他类型输入项均是来源契约错误，抛出 `TypeError`。它们不能充当 EOF。状态表中的 ASCII 字符条件按归一化字符数值判断，因此补充平面字符只可能作为字符串的原样字符被接受。完整字符串作为可迭代来源仍能用于已有调用，因为其每个迭代项是单字符字符串，而不是因为解析器假定整个文档保存在字符串中。

字符串适配器对每个块逐字符迭代。块边界可以出现在任意 UTF-16 位置，包括代理对中间；两个代理代码单元分别追加后，生成的字符串仍保留同一 UTF-16 内容。分段边界没有输入字符，不触发转移，不完成数字，不重置状态、缓冲区或待用键。对于其他来源，来源自身必须产出上述字符项。

生成器是惰性的：消费者开始取指令之前不读取来源；在一项或两项当前字符指令尚未交付时不读取下一个字符。消费者提前结束解析时，通过 `for...of` 的迭代关闭机制关闭来源。来源自己抛出的异常直接传播，不包装成 JSON 语法错误。

## 3. 唯一状态、唯一栈及附属数据

### 3.1 当前状态

大写短名仍指 `State` 类型的函数；`VA` 同时处理根起始和值起始，不另设根起始状态，因而保留全部 30 个状态。

只有一个变量 `state: State`，初值是 `VA`。本文的 30 个名字各对应一个接收字符并返回状态函数的函数。字符串内部、数字内部、容器内部及字面量内部的转移都改变这个同一变量；没有另一套词法状态，也没有令牌驱动的语法状态机。

下文所用的写入、关闭、十六进制累积等操作是普通辅助操作，不是状态，不保存另一个当前状态，也不编码成整数。将当前字符交给另一状态函数处理时，使用该函数返回的状态作为本次转移结果，不再次读取输入。

### 3.2 容器栈

只有一个栈 `containers: (JsonObject | JsonValue[])[]`，按外层到内层保存**正在生成的实际对象或数组引用**。栈顶为当前最内层尚未关闭的容器。栈元素不包装成语法帧，不保存返回状态、对象键、容器阶段或独立令牌。

通过 `Array.isArray(top)` 区分数组和对象；栈为空表示根层。栈只在消费 `{`、`[` 时压入实际容器，在消费相应闭括号时弹出。任何输入步骤只处理栈顶，不能越过栈顶关闭外层容器。

### 3.3 必需的非栈数据

| 数据 | 含义及生命周期 |
| --- | --- |
| `root: JsonValue \| undefined` | 根值。`undefined` 专指尚未写入；合法 JSON 值本身不会是 `undefined`。 |
| `pendingKey: string \| undefined` | 最近完整读出的、尚未接到值上的对象键。空字符串也是有效键，必须与 `undefined` 区分。 |
| `text: string` | 当前字符串的解码结果，或当前数字的原始拼写。开始对应值时清空或初始化，完成后不再需要旧内容。 |
| `hexValue: number` | 当前 `\u` 转义的十六进制累积值。读到 `u` 时设为零，在第四位完成后追加一个 UTF-16 代码单元。 |
| 输入位置 | 当前字符之前的 UTF-16 偏移、行、列，以及前一字符是否为 CR。只用于报错，不指导语法。 |
| 待输出指令槽 | 当前字符最多产生两条指令，可用两个可空变量保存。它们按产生顺序交付，不是栈，不保存语法。 |

不需要另存“字符串是键还是值”的控制状态：开始字符串时若栈顶是对象且 `pendingKey` 为 `undefined`，该字符串必为对象键；其余情况必为值字符串。字符串读取期间不改变容器栈或 `pendingKey`，所以在关闭引号上仍能用同一条件判定。

### 3.4 写入与父层恢复的不变量

**写入值 `attach(value)`：**

- 栈为空：必须尚无根值，将 `root` 设为该值。
- 栈顶为数组：将值追加到该实际数组。
- 栈顶为对象：必须存在 `pendingKey`；用它创建或替换普通可枚举自身属性，随后立即将 `pendingKey` 清为 `undefined`。

对象的 `__proto__`、`constructor`、`toString` 及空键均按普通 JSON 自身属性写入；不能通过赋值触发原型设置器。重复键以后一次完整写入为准。

**打开容器：**在消费 `{` 或 `[` 的同一步内先创建空容器，调用 `attach` 将其写入父容器或根位置，再压入同一个实际容器，最后产生对应的开始指令。开始指令交付时，消费者已经能在父结构中看到该空容器。

**关闭容器：**当前状态和栈顶类型必须允许该闭括号；弹出栈顶，产生对应的结束指令，进入 `OK`。空容器也如此。

关键不变量是：**打开子容器之前，父对象键就已被消费；子容器关闭后，父层一定处于“一个值之后”。**父键不必跨层保留，父层也不需要保存返回状态。子容器关闭后，`OK` 查看新的栈顶，直接决定父数组的逗号/`]`、父对象的逗号/`}`，或根层的空白/EOF。嵌套对象读取自己的键时，只需复用同一个 `pendingKey`。

除正在读键、等待冒号或等待对象值时外，`pendingKey` 必为 `undefined`。进入 `OK` 时它必为 `undefined`。一个父对象等待值时，若其值是容器，打开操作会在压栈前消除这个等待；若其值是简单值，完成写入时消除这个等待。

这使嵌套深度只影响容器栈长度：打开任意一层时先完成父层的写入责任，关闭该层时只有“返回父层的值之后”一种恢复位置。对子容器深度归纳，任何层都不需要留下父键、语法帧或返回状态；同时，实际栈顶类型和当前状态足以阻止越层关闭、漏冒号、漏逗号与尾逗号。

## 4. 状态表的记法与共同拒绝规则

本文使用以下互不含糊的字符集合：

| 名字 | 精确条件 |
| --- | --- |
| `W` | ` `、TAB、CR、LF，即 U+0020、U+0009、U+000D、U+000A。 |
| `D` | ASCII `0`–`9`。 |
| `NZ` | ASCII `1`–`9`。 |
| `H` | ASCII `0`–`9`、`a`–`f`、`A`–`F`。 |
| `B` | 可能终结数字的字符：`W`、`,`、`]`、`}`。是否符合所在容器，仍由 `OK` 判定。 |
| `R` | 来源契约允许、不是 `"`、不是反斜杠、字符数值不在 U+0000–U+001F 的原样字符串字符。 |

每个表格列出完整转移条件；委托处理的行仍必须通过被委托状态及父层条件，不能把进入该分支等同于整个字符转移已经成功。**未列出的所有字符一律在当前输入位置拒绝**，抛出 `JsonStreamError`，错误码为 `INVALID_JSON`。条件中的集合与单个字符按归一化后的字符数值相等或 ASCII 范围判断。不会忽略非法字符，也不会回退尝试其他语法。

“提交简单值”表示先 `attach`，再产生 `value` 指令。“开始字符串”表示把 `text` 清为空字符串。“结束对象/数组”采用第 3.4 节操作。表中的 EOF 是来源迭代器正常结束后的动作，**不是调用状态函数时传入一个伪字符**。

## 5. 容器与文档状态（6 个）

### 5.1 `VA`

**不变量/进入条件：**当前位置必须出现一个值；初始根层、对象冒号之后、数组逗号之后进入此状态。也可由 `AR` 在当前字符上委托它读取首个元素。若栈顶是对象，`pendingKey` 必已设置；栈顶是数组或栈为空时，`pendingKey` 必为 `undefined`。

| 当前字符 | 当前字符上的操作 | 下一状态 |
| --- | --- | --- |
| `W` | 无 | `VA` |
| `{` | 打开并立即写入空对象，压栈，产生 `startObject` | `OB` |
| `[` | 打开并立即写入空数组，压栈，产生 `startArray` | `AR` |
| `"` | 开始值字符串 | `ST` |
| `-` | `text = "-"` | `MI` |
| `0` | `text = "0"` | `ZE` |
| `NZ` | `text = 当前字符的 UTF-16 表示` | `IN` |
| `t` | 识别字面量首字母；暂不写值 | `T1` |
| `f` | 识别字面量首字母；暂不写值 | `F1` |
| `n` | 识别字面量首字母；暂不写值 | `N1` |
| EOF | 缺少必需的值，`UNEXPECTED_END` | 无 |

因此在该状态 `]` 与 `}` 都非法；数组逗号之后不能关闭数组，对象冒号之后不能关闭对象。

### 5.2 `OB`

**不变量/进入条件：**刚打开一个对象，栈顶必为该对象，尚未有第一个成员，`pendingKey` 为 `undefined`。

| 当前字符 | 当前字符上的操作 | 下一状态 |
| --- | --- | --- |
| `W` | 无 | `OB` |
| `}` | 结束空对象 | `OK` |
| `"` | 开始键字符串 | `ST` |
| EOF | 对象缺少闭括号，`UNEXPECTED_END` | 无 |

### 5.3 `KE`

**不变量/进入条件：**在对象成员之后读到了逗号；栈顶必为对象，`pendingKey` 为 `undefined`。此位置必须有新的键，不能再接受空对象的结束方式。

| 当前字符 | 当前字符上的操作 | 下一状态 |
| --- | --- | --- |
| `W` | 无 | `KE` |
| `"` | 开始键字符串 | `ST` |
| EOF | 逗号后缺少对象键，`UNEXPECTED_END` | 无 |

`}` 不在合法条件内，因此对象尾逗号被拒绝。

### 5.4 `CO`

**不变量/进入条件：**键字符串已完整读完，栈顶必为对象，`pendingKey` 已设置，尚未将任何值写入该键。

| 当前字符 | 当前字符上的操作 | 下一状态 |
| --- | --- | --- |
| `W` | 无 | `CO` |
| `:` | 保留 `pendingKey`，等待其值 | `VA` |
| EOF | 键后缺少冒号，`UNEXPECTED_END` | 无 |

### 5.5 `AR`

**不变量/进入条件：**刚打开一个数组，栈顶必为该数组，尚未有第一个元素，`pendingKey` 为 `undefined`。

| 当前字符 | 当前字符上的操作 | 下一状态 |
| --- | --- | --- |
| `W` | 无 | `AR` |
| `]` | 结束空数组 | `OK` |
| 其他字符 | 将**同一个字符**交给 `VA`，采用其操作及拒绝规则 | `VA(当前字符)` 的返回状态 |
| EOF | 数组缺少闭括号，`UNEXPECTED_END` | 无 |

最后一行字符委托不代表所有其他字符合法；合法起始字符精确等于 `VA` 中除 `W` 以外的九类条件。

### 5.6 `OK`

**不变量/进入条件：**一个值已完成：简单值已完整提交，或一个容器刚关闭。栈顶表示该值所在的父容器，栈为空表示根值已经完成。`pendingKey` 为 `undefined`。

| 当前字符及父层 | 当前字符上的操作 | 下一状态 |
| --- | --- | --- |
| `W`，任意父层 | 无 | `OK` |
| `,`，栈顶为数组 | 等待下一个元素 | `VA` |
| `]`，栈顶为数组 | 结束该数组 | `OK` |
| `,`，栈顶为对象 | 等待下一个成员键 | `KE` |
| `}`，栈顶为对象 | 结束该对象 | `OK` |
| EOF，栈为空且 `root` 已设置 | 产生 `endDocument(root)`，生成器返回 `root` | 文档完成 |
| EOF，栈不为空 | 父容器缺少闭括号，`UNEXPECTED_END` | 无 |

根层所有非空白字符均非法；对象中的 `]` 与数组中的 `}` 均非法。分隔符只作用于当前栈顶，不会寻找一个更外层的匹配容器。`root` 未设置而进入此状态是实现违反不变量，不能作为合法文档完成。

## 6. 字符串状态（6 个）

### 6.1 `ST`

**不变量/进入条件：**字符串打开引号已被消费，`text` 是已完成读取部分的解码文本；所有已开始的转义均已完成。由字符串开头、普通字符串字符、简单转义末尾及四位 Unicode 转义末尾进入。

| 当前字符 | 当前字符上的操作 | 下一状态 |
| --- | --- | --- |
| `R` | 将当前字符的 UTF-16 表示追加到 `text` | `ST` |
| 反斜杠 | 暂不追加，等待转义种类 | `ES` |
| `"`，栈顶为对象且 `pendingKey` 为 `undefined` | 将完整 `text` 设为 `pendingKey`，产生 `key` 指令；不创建属性 | `CO` |
| `"`，其余情况 | 将完整 `text` 作为字符串值提交 | `OK` |
| EOF | 字符串缺少关闭引号，`UNEXPECTED_END` | 无 |

原样 U+0000–U+001F 全部非法，包括 TAB、CR、LF；它们在字符串外可以是空白，但在本状态不得按空白处理。关闭引号本身不进入结果文本。

### 6.2 `ES`

**不变量/进入条件：**字符串中的反斜杠已经被消费，尚未读到转义种类，反斜杠尚未追加到 `text`。

| 当前字符 | 当前字符上的操作 | 下一状态 |
| --- | --- | --- |
| `"`、反斜杠、`/` | 将当前字符的 UTF-16 表示追加到 `text`，不追加字符数值的十进制文本 | `ST` |
| `b` | 追加 U+0008 | `ST` |
| `f` | 追加 U+000C | `ST` |
| `n` | 追加 U+000A | `ST` |
| `r` | 追加 U+000D | `ST` |
| `t` | 追加 U+0009 | `ST` |
| `u` | `hexValue = 0` | `U1` |
| EOF | 反斜杠后缺少转义种类，`UNEXPECTED_END` | 无 |

### 6.3 四位 Unicode 状态

进入这些状态期间，`text` 保持不变，只有 `hexValue` 累积。`hex(H)` 表示 ASCII 十六进制字符的值；每读一位执行 `hexValue = hexValue * 16 + hex(当前字符)`。

| 状态 | 不变量/进入条件 | 唯一合法字符与操作 | 下一状态 | EOF |
| --- | --- | --- | --- | --- |
| `U1` | 已读反斜杠与 `u`，尚无十六进制位；累积值为零 | `H`：累积第 1 位 | `U2` | 缺少第 1 位，`UNEXPECTED_END` |
| `U2` | 恰好已累积 1 位 | `H`：累积第 2 位 | `U3` | 缺少第 2 位，`UNEXPECTED_END` |
| `U3` | 恰好已累积 2 位 | `H`：累积第 3 位 | `U4` | 缺少第 3 位，`UNEXPECTED_END` |
| `U4` | 恰好已累积 3 位 | `H`：累积第 4 位，将 `String.fromCharCode(hexValue)` 追加到 `text` | `ST` | 缺少第 4 位，`UNEXPECTED_END` |

每个 `\uXXXX` 独立产生一个 UTF-16 代码单元。相邻的高低代理转义自然形成代理对；单独的高代理或低代理也保留，不强制补齐另一半。第 5 个十六进制字符在 `ST` 中作为普通字符处理。Unicode 转义不能提前结束，也不能用非 ASCII 数字充当十六进制位。

## 7. 数字状态（8 个）

`text` 在这些状态中始终保存已经消费的数字原始拼写；暂不写入父容器或根值。转换时使用 `Number(text)`，保留 `-0`，并采用 JavaScript 数值语义，包括有限精度、溢出得到正负 `Infinity`、下溢得到零。这里的溢出结果是合法数字拼写的转换结果；输入 `Infinity`、`NaN` 仍不是合法 JSON 文本。

本节状态表中的“追加”均指将当前字符的 UTF-16 表示追加到 `text`，不追加字符数值的十进制文本。例如字符值 0x31 追加的是 `"1"`，不是 `"49"`。

### 7.1 数字完成操作 `finishNumber(c)`

此操作不是额外状态，只能由已经形成合法完整数字的四个状态调用：`ZE`、`IN`、`FS`、`E3`。

当当前字符 `c` 属于 `B` 时，按以下顺序完成同一步：

1. 以完整 `text` 转换数值，调用 `attach` 写入，产生带 `raw: text` 的 `value` 指令。
2. 将**同一个 `c`**交给 `OK(c)`；采用其返回状态，或其错误。
3. 若本字符转移成功，生成器按顺序交付这一步的指令；无需把 `c` 放回来源，也不多读一个字符。

例如 `[1]` 的 `]` 同时完成 `1` 并关闭数组；同一步产生数字 `value` 和 `endArray`。`{"a":1,"b":2}` 的逗号同时完成数字并进入 `KE`。`1,`、`[1}`、`{"a":1]` 中的标点虽属于 `B`，仍由父层规则拒绝，不能因此接受文档。

在完成状态遇到 EOF 时，不存在分隔字符：直接提交数字，进入 `OK`，交付数字指令，再按 `OK` 的 EOF 规则检查整个文档。根数字据此完成；尚在容器内的数字虽已完整，但文档仍因缺少闭括号而报 `UNEXPECTED_END`。

## 8. 字面量状态（10 个）

首字母由 `VA` 消费。以下状态逐一验证剩余字母；不接受空白插入，不接受不同大小写。最后一个必需字母被消费时才提交简单值，然后进入 `OK`。

| `T2` | 已消费 `tr` | `u` | 确认第三个字母 | `T3` | 缺少 `u`，`UNEXPECTED_END` |
| `T3` | 已消费 `tru` | `e` | 提交布尔值 `true` | `OK` | 缺少 `e`，`UNEXPECTED_END` |
| `F1` | 已消费 `f` | `a` | 确认第二个字母 | `F2` | 缺少 `a`，`UNEXPECTED_END` |
| `F2` | 已消费 `fa` | `l` | 确认第三个字母 | `F3` | 缺少 `l`，`UNEXPECTED_END` |
| `F3` | 已消费 `fal` | `s` | 确认第四个字母 | `F4` | 缺少 `s`，`UNEXPECTED_END` |
| `F4` | 已消费 `fals` | `e` | 提交布尔值 `false` | `OK` | 缺少 `e`，`UNEXPECTED_END` |

| `N3` | 已消费 `nul` | `l` | 提交 `null` | `OK` | 缺少第二个 `l`，`UNEXPECTED_END` |

## 9. 写入时机与解析指令

| 被读取的内容 | 写入时机 | 指令 |
| --- | --- | --- |
| 对象 | `{` 被消费的同一步，空对象已经接到父层/根位置，然后压栈 | `startObject`，值为该实际对象引用 |
| 数组 | `[` 被消费的同一步，空数组已经接到父层/根位置，然后压栈 | `startArray`，值为该实际数组引用 |
| 对象键 | 关闭引号被消费时只设置 `pendingKey`，尚不创建属性 | `key`，携带解码后的键 |
| 值字符串 | 关闭引号被消费时才写入完整解码文本 | `value` |
| 数字 | 合法数字后读到 `B` 时，或合法完整数字状态收到 EOF 时 | `value`，含转换值和原始拼写 `raw` |
| `true`、`false`、`null` | 最后一个必需字母被消费时 | `value` |
| 容器关闭 | 合法闭括号被消费并弹栈时 | `endObject` / `endArray`，值为同一实际容器引用 |
| 整个文档 | 来源正常结束，所有状态和栈检查成功之后 | `endDocument`，携带根值，随后生成器返回同一根值 |

`startObject` / `endObject`、`startArray` / `endArray` 中的容器引用始终是活的；后续解析直接填充它们。同一个根容器的开始指令、结束指令、`endDocument` 与生成器返回值共享身份。不能为指令另造对象/数组副本。

一个当前字符最多产生两条指令：普通字符不产出指令；开括号、字符串关闭、字面量完成或独立闭括号各产出一条；完成数字并关闭容器时按 `value`、`endArray`/`endObject` 顺序产出两条。状态函数先同步完成当前字符的操作，生成器再交付对应指令。为此两个标量指令槽即可；不得将容器语法信息放进指令槽。

语法错误没有回滚承诺：已输出的指令、已暴露的实际容器保留已解析部分。在一个字符内，若数字已写入而随后分隔符的父层检查失败，该字符的暂存指令不交付，但已暴露的容器仍可能包含这个数字。EOF 完成数字时先交付数字指令，再检查尚未闭合的容器；例如 `[1` 可以在 EOF 输出 `value(1)` 后报错，绝不能输出 `endDocument`。消费者只有收到 `endDocument` 或正常取得生成器返回值，才拥有完整文档的验证结果。

## 10. 驱动、EOF 与错误位置

生成器的驱动顺序如下；这是调度约定，不是第二个状态机：

1. 通过 `for...of` 取得当前字符项，验证来源契约，并归一化为字符数值；不读取额外来源项。
2. 执行 `state = state(char)`。报错位置指向这个尚未计入的位置的字符。
3. 成功消费后更新位置，然后依次交付当前字符产生的零、一或两条指令。
4. 来源正常结束后，执行当前状态对应的 EOF 规则。

EOF 对 30 个状态的结果归纳为：

- `ZE`、`IN`、`FS`、`E3`：完成数字，转为 `OK`，再检查根/容器条件。
- `OK`：仅当栈为空且根值已设置时成功。
- 其余 25 个状态：必需语法尚未完成，报 `UNEXPECTED_END`。

这些规则恰好覆盖 30 个状态，不通过追加空白、闭括号或空字符串伪造输入来掩盖 EOF。空来源、只有空白的来源、未完成对象键、冒号前后、逗号之后、字符串与转义中间、字面量中间均不能完成文档。合法根数字在没有尾随空白时仍能正确完成。

JSON 字符错误使用 `JsonStreamError`，保留 `SyntaxError` 继承关系，包含错误码和 `{ offset, line, column }`。偏移从零开始，行列从一开始，偏移与列按消费的 UTF-16 代码单元计数。消费 CR 后行加一、列重置为一；紧随 CR 的 LF 只重置列，不再增加行；单独 LF 增加行并重置列。普通字符的列增加其 UTF-16 表示长度：BMP 字符或独立代理代码单元为一，补充平面字符为二。EOF 错误位于全部已消费输入之后。

来源契约错误使用 `TypeError`；内部不变量被破坏属于实现错误，不可伪装成一个合法解析路径。本文不规定人为突变已暴露容器时的结果；消费者需要把活引用当作解析器拥有的结构，待完整文档后再修改。

## 11. 少量逐字符轨迹

### 11.1 打开即写入、消费父键、关闭后恢复：`{"a":[{"b":1},2]}`

表中栈写成从外向内的实际引用；`O` 为根对象，`A` 为 `O.a` 数组，`B` 为其第一个对象。

| 字符 | 进入的状态 | 当前字符上的结果 | 返回状态 | 容器栈 / 待用键 |
| --- | --- | --- | --- | --- |
| `{` | `VA` | 创建 `O` 并设为根，输出开始对象 | `OB` | `[O]` / 无 |
| `"` | `OB` | 开始键字符串 | `ST` | `[O]` / 无 |
| `a` | `ST` | `text = "a"` | `ST` | `[O]` / 无 |
| `"` | `ST` | 完成键，尚未创建 `O.a` | `CO` | `[O]` / `a` |
| `:` | `CO` | 等待值，保留键 | `VA` | `[O]` / `a` |
| `[` | `VA` | 创建 `A`，先写入 `O.a = A`，消费键，再压栈 | `AR` | `[O,A]` / 无 |
| `{` | `AR` | 同字符交给 `VA`：创建 `B`，先追加到 `A`，再压栈 | `OB` | `[O,A,B]` / 无 |
| `"` | `OB` | 开始键字符串 | `ST` | `[O,A,B]` / 无 |
| `b` | `ST` | `text = "b"` | `ST` | `[O,A,B]` / 无 |
| `"` | `ST` | 完成子对象键 | `CO` | `[O,A,B]` / `b` |
| `:` | `CO` | 保留键，等待值 | `VA` | `[O,A,B]` / `b` |
| `1` | `VA` | 只保存数字拼写，此时尚无 `B.b` | `IN` | `[O,A,B]` / `b` |
| `}` | `IN` | 写入 `B.b = 1` 并消费键；同一个 `}` 关闭 `B`；输出数字和结束对象 | `OK` | `[O,A]` / 无 |
| `,` | `OK` | 栈顶为 `A`，等待下一个数组元素 | `VA` | `[O,A]` / 无 |
| `2` | `VA` | 保存数字拼写，尚未追加到 `A` | `IN` | `[O,A]` / 无 |
| `]` | `IN` | 追加 `2`；同一个 `]` 关闭 `A` | `OK` | `[O]` / 无 |
| `}` | `OK` | 栈顶为 `O`，关闭根对象 | `OK` | `[]` / 无 |
| EOF | `OK` | 输出完整文档，返回 `O` | 完成 | `[]` / 无 |

这里没有保存父对象键 `a` 的副本：`[` 时该键已用于写入，之后复用同一个待用键读取 `b`。也没有保存父层返回状态，弹栈后统一进入 `OK` 即足够。

### 11.2 分段边界不完成数字：来源块 `["[1e", "+", "2,", "null]"]`

块先由 `characters` 适配；解析器看见的连续字符为 `[1e+2,null]`。

| 字符/边界 | 进入的状态 | 操作 | 返回状态 |
| --- | --- | --- | --- |
| `[` | `VA` | 创建并写入根数组 | `AR` |
| `1` | `AR` | 委托 `VA`，开始数字 | `IN` |
| `e` | `IN` | 追加指数标记 | `E1` |
| 块边界 | — | 不向解析器提供输入项；保留 `text = "1e"` | 不变 |
| `+` | `E1` | 追加符号 | `E2` |
| 块边界 | — | 保留状态和缓冲区 | 不变 |
| `2` | `E2` | 追加第一位指数数字，仍未写值 | `E3` |
| `,` | `E3` | 写入数值 `100`，`raw = "1e+2"`；同一个逗号进入下一元素 | `VA` |
| 块边界 | — | 不触发 EOF | 不变 |
| `n` | `VA` | 识别首字母 | `N1` |
| `u` | `N1` | 确认字母 | `N2` |
| `l` | `N2` | 确认字母，尚未写入 | `N3` |
| `l` | `N3` | 完整字面量才追加 `null` | `OK` |
| `]` | `OK` | 关闭根数组 | `OK` |
| EOF | `OK` | 完整文档，结果 `[100, null]` | 完成 |

### 11.3 Unicode 与值字符串跨分段：来源块依次为 `"`、反斜杠、`u4`、`F6`、`0`、`"`

完整文本是 `"\u4F60"`，结果为字符串 `你`。

| 字符 | 进入的状态 | 操作 | 返回状态 |
| --- | --- | --- | --- |
| `"` | `VA` | 开始字符串；根尚未写入 | `ST` |
| 反斜杠 | `ST` | 等待转义 | `ES` |
| `u` | `ES` | 累积值归零 | `U1` |
| `4` | `U1` | 累积第一位 | `U2` |
| `F` | `U2` | 累积第二位 | `U3` |
| `6` | `U3` | 累积第三位 | `U4` |
| `0` | `U4` | 得到 U+4F60，追加 `你`；根仍未写入 | `ST` |
| `"` | `ST` | 完整字符串才写入根，输出 `value("你")` | `OK` |
| EOF | `OK` | 完整文档 | 完成 |

任意块边界都仅保持状态。与之不同，若来源在 `U4` 正常结束，那是真正 EOF，缺少第四位，必须报错。

### 11.4 空容器与尾逗号的分歧

| 输入 | 必须出现的路径及结果 |
| --- | --- |
| `[]` | `VA` —`[`→ `AR` —`]`→ `OK` —EOF→ 成功 |
| `{}` | `VA` —`{`→ `OB` —`}`→ `OK` —EOF→ 成功 |
| `[0,]` | `0` 后处于 `ZE`；`,` 完成数字并进入 `VA`；该状态拒绝 `]` |
| `{"a":0,}` | `,` 完成数字并进入 `KE`；该状态拒绝 `}` |
| `12` | 第二位后为 `IN`；EOF 提交根数字再完成文档 |
| `[12` | 第二位后为 `IN`；EOF 提交数字，但栈仍有数组，因此报 `UNEXPECTED_END` |

## 12. 文档覆盖核对清单

以下项目是对本设计规范的覆盖与一致性核对，不是实现测试结果。本阶段没有编写或修改解析器，没有运行解析器测试，也没有进行 C 参考实现对照。

- 状态数量：容器/文档 6 + 字符串/转义 6 + 数字 8 + 字面量 10 = **30**。
- 每个状态均有不变量、进入条件、完整合法字符条件、操作和下一状态；表外字符共用明确的拒绝规则。每个状态均有 EOF 行。
- 根值覆盖对象、数组、字符串、数字、两个布尔字面量和 `null`；仅空白、两个根值与根后非法字符被拒绝。
- 容器覆盖空容器、首项、后续项、冒号、完整值之后及跨层关闭；对象与数组尾逗号由不同的必需输入状态拒绝。
- 字符串覆盖所有原样字符限制、全部简单转义、恰好四位十六进制、代理代码单元和真实 EOF。
- 数字覆盖负号、零、非零整数、小数、指数标记、指数符号、指数数字、分隔符复用以及根数字 EOF 完成。
- 三个字面量逐字母完整覆盖；不完整字面量不写入，非法后继由 `OK` 拒绝。
- 只有一个实际容器栈；对象键在打开子容器之前被消费，父层恢复依靠弹栈后的实际容器类型，不依赖第二个栈或返回状态栈。
- 解析器本身为生成器，以 `for...of` 消耗字符来源；上游分段不成为语法事件；任何结束指令都不能代替文档 EOF 验证。
- 字符表示与字符来源分开：状态使用字符数值，来源既可直接产出数值也可产出兼容的单字符字符串；裸 Iterator 需具备或包装出 Iterable 能力，不能假定有 `next()` 就能用于 `for...of`。
